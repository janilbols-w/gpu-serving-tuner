# 指标、稳态与可信度

## 基本指标

对单请求：

- `TTFT = first_token_time - request_start_time`
- `E2E = request_end_time - request_start_time`
- `TPOT = (E2E - TTFT) / max(output_tokens - 1, 1)`
- `ITL`：相邻输出 token 时间间隔；说明是否包含首 token。

对服务：

- 输入吞吐 = 完成请求的输入 token / 稳态时长；
- 输出吞吐 = 完成请求的输出 token / 稳态时长；
- 每卡吞吐 = 服务吞吐 / 实际参与该角色的 GPU 数；
- 成功率 = 成功请求 / 总请求；
- keep-up：实际发出负载与目标负载的差异不超过预设容差，且 backlog 不持续增长。

缓存命中输入、未命中输入和输出 token 的成本与计算意义不同，不要无说明地合并后跨命中率比较。

## 统计窗口

预先定义 warmup、steady 和 cooldown。只在 steady 窗口内计算主要指标，并保存窗口起止时间、时区和请求数。

长稳态中同时查看：分位延迟、窗口吞吐、错误率、backlog、GPU 利用率/功耗/显存、缓存命中和角色队列。平均值可能掩盖周期性抖动和尾部退化。

## 可比较性

比较前逐项确认：硬件、GPU 数、运行时身份、模型 revision、负载分布、生成器模式、命中率、采样参数、统计窗口和指标实现。

不同口径只能在明确归一化后比较，并说明归一化假设。不能把并发测试与开环速率测试直接排名。

## 不确定性

- 至少保存单次原始结果，不只保存平均值。
- 对关键点重复运行并报告范围、标准差、置信区间或 bootstrap 区间之一。
- 先用 anchor 估计当前环境噪声；收益没有超过噪声时判为证据不足。
- 尾部分位需要足够样本；样本不足时标记 `insufficient-samples`。
- 短测适合筛选，边界结论需要更长窗口或重复 seed。

不要在 skill 中固化跨环境通用的噪声百分比或显著性阈值。阈值应来自当前压测器、样本量和 anchor 重复测试。

## 有效性门禁

仅当以下条件全部满足时，run 才可进入性能排名：

1. 元数据完整；
2. 请求与输出通过正确性检查；
3. 负载生成器 keep-up；
4. 错误率和用户定义 SLO 通过；
5. 稳态窗口有效且样本充分；
6. 无未解释的服务重启、资源争用或环境变化。

未通过的 run 保留 `invalid_reason`，用于诊断而不是删除。
