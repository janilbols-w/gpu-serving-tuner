# 调优诊断手册

先分类瓶颈，再选参数。表中的方向是诊断起点，不是跨环境通用结论。

## 症状到实验

| 症状 | 优先确认 | 候选实验 |
|---|---|---|
| TTFT 中位数和长尾同时上升 | prefill 计算、排队、输入长度 | prefill 并行、chunk、prefill 并发槽 |
| TTFT 主要是长尾恶化 | 调度、KV 传输、抖动、路由 | 传输后端、路由策略、队列隔离 |
| TPOT 恶化 | decode 批大小、图覆盖、投机接受 | decode 并发、graph 配置、投机参数 |
| 吞吐上升但 `keeps_up=false` | 生成器 backlog、服务过载 | 降一档并重测，不排名该点 |
| 命中场景反而变慢 | 缓存查找、同步、传输开销 | 关闭/开启缓存 A/B，拆分命中路径 |
| 跨天结果变化 | JIT/cache、邻近负载、频率、镜像漂移 | 重跑 anchor，比较五类身份 |
| 健康但 P/D 不工作 | 注册成功但真实数据路径失败 | 真实生成、传输日志、角色指标 |

## 变量类型

**水平变量**是互斥方案，例如路由策略或并行布局。使用小规模 A/B/C，保持其他条件相同。

**叠加变量**可以组合，例如原生配置、缓存、量化、补丁。先建立最小可用基线，每次只增加一层；每层都跑正确性和 anchor。

**bundle** 是由于依赖关系必须一起改变的参数组。记录整个 bundle 的效果，不把收益虚假归因到其中一个 flag。

## P/D 系统

- 分别记录 prefill、decode 和 router 的角色特有参数。
- 健康检查、注册检查、普通生成、真实 KV 传输和性能测试是不同门禁。
- fake P/D、固定接受长度或模拟传输可用于隔离计算与通信，但必须标记为模拟。
- 角色数量相同不代表运行路径相同；应对比最终 argv、环境、镜像、补丁和运行时日志。

## 补丁与编译

只有在原生配置无法验证假设时才引入补丁。记录：来源、目的、适用 revision、修改文件、构建命令、产物身份、ABI/依赖限制、验证步骤和回滚方式。

补丁应用前先 check 或 dry-run；构建结果用 digest 或校验和标识。容器内手工修改若不能导出和复现，只能作为探索证据，不能进入最终 recipe。

## 决策语言

结论使用三态：

- **保留**：门禁通过，收益稳定，成本可接受；
- **放弃**：无收益、正确性失败或复杂度不值得；
- **待定**：证据不足，并明确需要哪一次测试解除不确定性。

避免写“某方案最好”；应写“在指定硬件、运行时、负载和 SLO 下，该方案在已测候选中占优”。
