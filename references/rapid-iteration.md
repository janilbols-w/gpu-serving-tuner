# 快速迭代方法

## 漏斗式测试

把测试预算按证据强度逐级增加：

1. **静态检查**：语法、参数、路径、镜像和资源计划。
2. **smoke**：最小请求，验证端到端可用和输出基本正确。
3. **anchor**：固定代表性点，用于检测环境漂移。
4. **短测**：低成本筛选和寻找性能拐点。
5. **边界复测**：在候选容量附近重复并上下各测一档。
6. **长稳态**：确认漂移、泄漏、长尾和热状态。
7. **扩展矩阵**：只为晋级候选覆盖更多长度、命中率或并发。

失败越早发现，浪费的 GPU 时间越少。

## 实验臂

可以并行运行多条探索臂，但每条必须独占：

- GPU 或 MIG 资源；
- 服务端口和管理端口；
- 容器名或进程标识；
- 结果目录；
- 编译/JIT/模型缓存目录。

如果无法证明无干扰，就串行运行。只有一条臂进入昂贵确认阶段时，其他臂可以继续做不争抢资源的静态分析或低成本准备。

## 晋级门禁

候选只有同时满足下列条件才晋级：

- 请求成功且输出正确；
- 负载生成器达到目标，`keeps_up=true` 或等价条件成立；
- SLO 和错误率通过；
- 相对 anchor 的收益超过测量噪声；
- 没有引入不可接受的复杂度或运维风险。

## 退出条件

每个变量在开始前定义：最大档位数、最大失败次数、最低有意义收益和回滚条件。连续档位没有稳定收益、正确性失败或复杂度超过预算时停止。

## 快速但不草率

- 短测用于排序，不用于宣布最终容量。
- 单次运行用于发现，不用于证明。
- 把失败点保留下来，它能帮助定位 knee 和错误模式。
- 跨环境比较前重跑 anchor；anchor 漂移时先调查环境，不继续堆实验。
- 自动化重复劳动，但保留最终 argv、原始输出和显式决策，避免“自动化黑盒”。
